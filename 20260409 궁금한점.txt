하나 또 궁금한게 생겼어

만약 내부클래스를 부모클래스 내부에 자바로 만들었다고가정하면

그 클래스를 다른 자식 클래스가 상속받았을 시 



메인 메소드에서

참조변수를 부모클래스 타입으로 만들고 자식클래스의 인스턴스를 만들었다고 가정하면

그럼 부모 클래스 내부의 내부클래스 내부의 메소드들도 자식은 상속전부 받는거야?

따로 생성자처럼 내가 SUPER로 뭔가를 올려줘야하는건 없나?

그리고 부모타입의 참조변수이기에 해당 내부 클래스의 메소드들도 호출이 가능한거야? 



class Parent {
    class Inner {
        void print() { System.out.println("내부 클래스 메소드 호출!"); }
    }
}

class Child extends Parent { }

// 메인 메소드 상황
Parent p = new Child();




Parent p = new Parent(); // 1. 바깥 객체(주인) 먼저 생성
Parent.Inner inner = p.new Inner(); // 2. 주인 p를 통해서만 생성 가능 (p.new 문법)


이경우

p.print()가 문제없이 가능하다


그니까 너는 2번쨰 줄에서 인스턴스 생성시

Parent.Inner로 부모클래스의 내부클래스 타입의 참조변수 inner을 생성 

근데 그 당시에 p.new를 왜써야하는거임

new는 애초에 힙영역의 방을파는건데 


Parent.Inner inner = p.new Inner(); // 2. 주인 p를 통해서만 생성 가능 (p.new 문법)


여기서 그럼 너 말은

애초에 부모 클래스의 이너 클래스타입의 참조변수의 조종을 받는 인스턴스 생성을 하려면

부모클래스의 참조변수의 조종을 받는 인스턴스가 이미 메인메소드내부에 생성 되어있어야지만 가능하다는거임?






2.

그럼 궁금한건 왜 이너 클래스가 자바에서 ENCAPSULATION을 위해 필요한거야?

그냥 부모님의 필드변수를 PRIVATE으로 묶고 그냥 메소드를 PUBLIC으로 열어줘서 PUBLIC인 메소드로 외부랑 소통하면되고 그럼 번거롭게 인스턴스 생성규칙( 부모클래스 내부에 이너클래스 존재시의) 을 따를 필요도 없어지잖아 



맞다 그냥 게터세터로만 소통하고 부모클래스에 인스턴스 변수와 인스턴스 메소드가 덕지덕지달려있음 추후 스파게티 코드가 되기 쉽기에
PRIVATE으로 변수를 묶어두어도 내가 이너 클래스 생성한걸로 다른 외부 클래스들과는 다르게
해당 클래스 내부의 인스턴스 변수들에 게터 세터 안쓰고도 접근이 가능하게끔하기에 캡슐화에 매우 용이하다.

3. 추상클래스의 추상메소드처럼 인터페이스의 메소드역시 추상메소드인데 왜 abstract가 안붙어있나

abstract는 추상클래스 내부에서 무조건 메소드 사용시 달아줘야한다 ( 추상메소드일시)
근데 인터페이스에는 생략되어있는 모습이 자주 보여 궁금해졌는데
알고보니 그냥 abstract의 기능을 그대로 하는 추상메소드이고 그저 abstract를 생략한걸 알수있다.
고로 정리하자면

추상 클래스 내부의 추상메소드에는 강제적 의무적으로 abstract를 메소드앞에 달아줘야하고 

인터페이스의 기능을 구현할경우에는 강제적으로 그 기능에 abstract를 달아줄 필요가없는것이다.
고로 생략이 가능함

여기서 궁금한건

추상 클래스 내부에 일반 메소드 (인스턴스 메소드 ) 들의 생성이 가능한가?
가능하다
이 경우에는 이 추상 클래스를 상속받는 자식클래스들이 이 메소드들을 강제적으로 오버라이딩 할필요가없다 말그대로 optional 한것이다.
그럼 
인터페이스의 경우에는 기능이라는 추상클래스 제외 다른 기능들을 넣을수있을까?
java 8 이후의 경우에 default 접근제한자를 붙일경우에 default 메소드들을 제작을 가능하다
이경우에 위 추상 클래스 내부의 일반 메소드들과 같은 영향력을 가진다.
