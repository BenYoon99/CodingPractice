메서드 

사용자 메서드 내부에 - 정적 메소드는 static 메소드 이기에 코드의 런타임 도중에 생성된다( 게시판과 칠판을 생각하면 편하다 )


예시로 

프로그램의 특정 인스턴스가 참조변수를 통해 정적 메소드를 소환했다면

다른 인스턴스가 해당 메소드를 사용할떄 역시 같은 결과값이 출력된다

추후 메인메소드에서 다른 인스턴스가 수정시 수정된 값으로 모두가 공유하게된다.


스태틱 메소드는 이름명만으로도 호출이 가능하다  // 여기 이해안감 어떻게 이름만으로 호출이 가능하다는거지?

메서드 오버로딩

메서드의 이름은 같지만 파라미터가 다른 여러 것들을 같은 명의 메서드로 정의하는것

메서드 오버로딩의 조건

- 메서드이름이 같아야한다

- 매개변수의 자료형이나 개수가 다르다.



근데 결국 파라미터가 다르기에 클래스내부에 다 직접 일일이 만드는것 같은거자나 이름만 통일할뿐 ?
이게 내 의문점임

- 만드는 코더는 힘들겠지만 ㅇㅇ, 호출자 (사용자) 입장에서 해당 메소드들을 일일이 외울필요없이 클린코드적으로 하나의 메소드명을 그냥 그대로 먹으면 됨 ( pay - payInt payLong payDouble 할필요없다)



여기서 그럼 

pay를 오버로딩친다고 가정하면

int pay()        

double pay()

이렇게 데이터형으로 오버로딩도 가능하고

int pay ( int x)

double pay ( int y)

이렇게 둘로 뺄수도 있는거라는거임?



--불가능하다

생각해보면

내가 가령

ben.pay() 를 메인메소드에서 박으면

메인메소드에서 int형 반환 pay인지 double형 반환 pay인지 알수없기에

그럼

여기서 더 궁금한건 

ben 클래스 내부에

int 형 반환 pay 파고 


ben1 클래스 내부에

double 형 반환 pay 파면

그럼 이 경우에 

이렇게 오버로딩은 안되는거임?

애초에 참조변수가 다를텐데;


이 경우는 참조변수가 아니다 
그저 동명이인처럼
같은 이름의 메소드가 서로다른 클래스에 존재하는것 뿐이다.

메서드 오버로딩의 기본 전제조건이

한 클래스 내부에서 같은 이름의 메소드가 다른 파라미터와 다른 데이터반환타입으로 다양하게 존재하는 경우를 말하는거임
