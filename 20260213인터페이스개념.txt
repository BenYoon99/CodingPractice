인터페이스 interface

인터페이스란 규격을 제시해주는 하나의 껍데기이다

예를 들어보자

우리가 회사를 운영한다면

그 안에는 알바생 비정규직 인턴 정규직들에게 돈을 주기 위해 

payment를 사용해야하지만

다양한사람들이 코딩을 하여 DB를 관리할떄 

메소드명을 

누구는 albaPayment 누구는 internPayment 

누구는 normalPayment  누구는 instablePayment

이렇게 다 다르게 하게되면 

관리하기가 힘들어진다.

이경우에 관리의 개념에서 큰 틀에서

모두를 한 틀로 보면 급여를 지급하는것이다

고로 이경우 

인터페이스라는 껍데기를 사용하여

모두에게 저 메소드의 규격을 하나로 강제 통일해서 
이쁘고 효율적이게 관리가 가능하다


코드를 하나 보여주겟다

interface Payment {

	int payment(); 
}

class internPayment implements Payment {

	@Override
	
	int payment(){
		return wage;}
}
이런식으로 짤수있다

implements로 받고

더군다나 부모클래스 상속받으면서 인터페이스껍데기까지 받을수있다

이경우

부모클래스명이 bankSalad라면

internPayment extends bankSalad implements Payment 

이렇게되면 부모의 필드 전부 상속받으면서 

페이먼트 인터페이스의 메소드를 오버라이딩이 강제되는 상황이 되는것이다 

부모의 메소드들은 굳이 오버라이딩 하지 않아도 되는거지만

인터페이스는 무조건 오버라이딩을 해야하는것이다 
그 점에서 큰 차이가 있다

약간 내가 혼자 공부하면서 느낀건

부모 클래스에 기능없는 버튼만 판 상황에서 

자식클래스 오버라이딩하는경우가 있는데

이경우면 인터페이스를 굳이 안써도 되는게 아닌가싶다

그렇게 해주고 그냥 자식이 상속받는경우 다 해주면되니까

하지만 상속을 안받는 친구들도 있을수있으니 그 경우 인터페이스 사용하는게 좋겟다
하지만 상속받는 친구들끼리의 일이면
그냥 부모에게 기능없는 메소드칸 하나 만들어주고 
그걸로 오버라이딩 쳐도 될것같다.


부모에게 기능없는 메소드칸을 만들어주는것처럼 ( 부모의 규격을따르는 참조변수로 자식의 규격따르는 인스턴스 조종시 
자식 에게만 있는 메소드 못사용해주니까 그떄 만들어주는것 )
처럼 기능이 없이 만들어줘야한다 인터페이스 생성시 강제하는 메소드는.
왜냐하면 그걸 받는 친구들이 전부 오버라이딩해서 내용을 채워줘야하기떄문이다 .
다형성은 
인터페이스에서 어떻게 발휘될까를 제미나이가 생각해보라고 한다.

흠 .. 다형성이란 한 규격을따르는 참조변수로 다양한 다른 클래스의규격을따르는 참조변수들을 조종하는걸 말하는건데

그럼 인터페이스의 규격내의 메소드를 다양한 클래스들이 받아서 만들었다면

그 클래스들은 공통 메소드를 갖게되는것이기에

나중에 그 클래스들을 부모클래스 규격으로 배열을 파서 묶어주거나 
잠시만 부모클래스로 묶으면 애초에 사용이불가함 부모에게없다면
근데 부모가 갖고있다하고 부모 - 자식간이면 그냥 부모에게 비어있는 기능칸 만들어주면되는데.. 흠..
ㅅㅂ 배열을 인터페이스 받는놈들끼리도 팔수있다고한다

고로 인터페이스 받는놈들끼리면 
누구는 부모에게 상속받은놈도 

누구는 상속안받은 그냥 평범한놈 1도
그냥  저 Payment를 받았다면

전부 배열에 묶어서 동일관리가 가능하다 <----- 다형성 !!!!!






여기서 중요한게

상속과 인터페이스의 큰차이


상속은 수직적 다형성이야

너랑 나는 상속관계다 
같은 부모 자식간에만 묶일수있는데


인터페이스는 수평적 다형성임

부모가 다른관계 , 부모가 없는놈  이런놈들도 하나로 묶일수있음


예를 들어보겠음

ex) 부모 클래스 이하 부모 자녀클래스 이하 자녀

부모3-자녀3-Payment

부모4 - 자녀4 - Payment


이경우에 부모클래스가 2 3 4 로 다른

자녀 2 3 4는 Payment 라는 인터페이스를 받기에

배열

Payment [] paymentFam = new Payment[3];
paymentFam [0] = 자녀2;

	for ( Payment p : paymentFam){

			}
