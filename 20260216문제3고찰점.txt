왜 인터페이스에서 구현하는 메소드에는 꼭 public을 붙여줘야하나에 대한 공부




interface RemoteControl {
    public void turnOn();
}
class TV implements RemoteControl {
    @Override

    public void turnOn(){
        System.out.println("TV 전원을 켭니다");
    }
}
class Main {
    public static void main(String[] args) {
        TV tv = new TV();
        tv.turnOn();
        
    }
}

이렇게 인터페이스가 있고

TV클래스가 있다

TV클래스는 인터페이스 내부의 turnOn이라는 메소드를 구현중이고

이 경우에 interface는 무조건 public ( 공유를 하는것이기에" 공공의 ") 
이다

고로 자바는 그 경우 구현받을시 강제되는 메소드 앞은

당연하게도 public 이겟거니 판단하여 

생략해도 가능하다 하지만
 

그 인터페이스의 기능을 구현하는 클래스에는 
중요한 법칙이 작용한다

절대 인터페이스의 기능을 구현하는 클래스의 오버라이딩된 메소드는
절대로 그 인터페이스의 메소드의 접근 제어자보다 좁아질수 없다는 
원칙을 갖고있는데

public 즉 전체공개의 인터페이스의 메소드의 접근 제어자(가장 큰것) 보다 

만약 더 작아지면 안되는건데

말그대로 가장 큰것이기에

아래 구현해야하는 클래스 내부의 메소드역시 접근 제어자가 public으로 강제되는것이다



고로 인터페이스의 강제하는 메소드역시 public 그리고 그걸 받는
놈이 오버라이딩하는경우에도 public 박아줘야한다 



접근 제어자의 크기는 총 네단계다
