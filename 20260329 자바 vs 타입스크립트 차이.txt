// 20260329 자바 vs 타입스크립트 차이


1.공통점

자바와 타입스크립트는 백엔드에서 주로 사용되는 언어다.


2.큰 틀의 차이점

	2-1 근본적 정체성
	
		Java는 JVM 위에서 구동되는 완벽히
		독립된 언어이다.

		TypeScript는 결국 JavaScript의
		동적타이핑 에러를 잡기 위해 탄생한
		정적 타이핑 상위 집합이기에
		결국 JS로 컴파일 되어 실행된다.
		비 독립적.

	2-2 컴파일 및 실행 매커니즘
	
		Java의 컴파일
	
		.java 소스 코드를 javac 컴파일러가
		**바이트코드로 바꾼다.
		그 뒤 JVM에서 OS 에 맞는 기계어로 		해당 바이트코드를 해석한다.
	
		이 방식의 장점: 플랫폼 독립성, 강력		한 최적화 기능( JIT 컴파일러)

	
		TypeScript의 컴파일

		.ts 코드를 tsc 컴파일러가 **자바스크립트(.js)**로 변환합니다.
	
		변환된 JS가 Node.js 환경이나 브라우저의 V8 엔진에서 실행됨.
	
		이 방식의 특징 : 실행시점의 정보
		가 사라진다. 개발 단계의 안정성만을 목표로 하는 도구임.

	3 타이핑 시스템

		항목  Java (Strong/Static),  *TypeScript (Structural/Static) 타입 체크

 		엄격함. 선언하지 않으면 사용 불가.  					*유연함. 인터페이스 구조만 맞으면 허용. 명시성

		모든 변수에 타입을 명시해야 함.                   				*타입 추론(Type Inference)이 강력함.
		다형성,상속과 인터페이스를 통한 엄격한 계층 구조.            	*덕 타이핑(Duck Typing) 기반의 유연한 구조.
	
	4. 동시성 모델 ( Concurrency)

		Java ( 멀티스레드 )
			여러개의 스레드를 동
		동시에 돌려 작업처리를한다.
			CPU 코어를 100% 활용하기에 좋지만
		스레드 간의 데이터 충돌을 관리하는 능력
		이 고급 개발자의 척도이다.

		TypeScript/Node.js
		스레드는 한개이지만 비동기를 통해멈추지않고 일을 처리한다.
		가벼운 요청이 수만 개 들어오는 환경에는유리하지만,연산이 복잡한 작업(AI 계산 등) 에는 좋지않다.
	
	5. 생태계 및 활용도

	활용도의 차이에는

	Java (Spring Boot)

			금융권 , 이커머스 , 공공기관등 - 절대 죽으면 안되는  대규모 시스템

		수십명의 개발자가 협업하는 대형 프젝

		안정적인 라이브러리와 수십년간 쌓인 유지보수 노하우


	TypeScript ( NestJS/Express)
	
		스타트업 ,실시간 서비스

		프론트엔드와 같은 언어를 사용해서
		풀스태ㄱ 개발 생산성 극대화

		빠른 프로토타이핑과 배포가 생명인 서비스다.
