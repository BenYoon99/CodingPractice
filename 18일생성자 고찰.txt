//생성자 고찰



예를 들어보자




Bulgogi bulgogi = new Bulgogi();

이 한줄의 신택스를 해석하면

우리는 이렇게 이해가 가능하다

Bulgogi라는 클래스의 규격을 따르는 참조변수 bulgogi를 스택영역에 만들고 

힙 영역에 새롭게 공간을 만들어주고 

만든 공간에 Bulgogi의 규격을따르는 인스턴스 생성 ( 따로 생성자로 받는 인자값이 없기때문에 ) 

그냥 데이터없는 그냥 인스턴스 생성

이 경우 IF

Bulgogi bulgogi = new Bulgogi("불고기");

이고 

class Bulgogi {

String name;


	Bulgogi(String name){
	this.name = name; }

} 

이라면 

나는 저 설명에서 만든 공간에 Bulgogi의 규격을따르는 불고기라는 name의 데이터값을 달고 태어나는 인스턴스를 생성하는것이다 ( 인자값 전달 , 그것을 달고태어남) 

여기서 헷갈리면 안되는것이 

new Bulgogi("불고기");

의 불고기라는 값은 실질적 데이터값을 내가 직접 넣어주는 
그런 데이터값 한마디로 인자 Argument인데

Bulgogi(String name) 
의 String name은

이 메소드에는 이러한 인자를 받겠슴당~~~ 이라는
매개변수이다 
파라미터라고도 부르지
이경우는 이 메소드를 선언하는 클래스내부에 존재하겠지.



그럼 이러한 생성자는 왜 중요한걸까

생성자는 
3가지 이유로 매우중요하다

1. 클래스 내부에 인스턴스 변수의 값을 굳이 갖게 안해줄수있다

클래스내부의 정해진 인스턴스 변수값은 문신이다 
문신없애기 문신을 없앱시다 

2. 데이터 무결성 보장 (data integrity ensurance)

이름을 무조건 달고태어나야하는 객체들의 모임을 만든다하면

클래스내부에서 그 객체들이 이름을 가져야만 태어날수있게금 강제시
안만드는 실수하게되면 컴파일에러가떠서 
실수를 고치게해준다
혹여나이렇게안하면

이름없는챔피언이 롤에 나뒹구게되고 게임 터짐

3. 노가다 방지

선언과 동시에 이름이나 인자값을 넣어주기에
추후 그 참조변수 . 무엇을 안해줘도된다 그 한줄을 세이브함 

그럼 저 경우 생성자에서 this 라고 하는것이 가리키는것이 정확히 무엇일까? 확실히 이해하자 

this란 
인스턴스 객체 생성시 생성되는 그 인스턴스를 가리키는 클래스내부의 참조변수이다 
그니까 힙영역의 클래스 내부에서 만들어놓은 힙영역에 인스턴스 생성시 그 인스턴스를 가리키게끔 하는 참조변수인거다
