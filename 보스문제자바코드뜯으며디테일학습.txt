class Unit {
    int hp = 10; // [부모의 방]
    void upgrade() { hp += 10; }
}

class Medic extends Unit {
    int hp = 5; // [자식의 방] - 이름이 같아서 부모의 hp를 가려버림 (Shadowing)
    @Override
    void upgrade() { hp += 5; } // [오버라이딩] - 호출 시 무조건 이놈이 우선권 (Dispatch)
}

        // 메모리 안에는 Unit의 hp(10)와 Medic의 hp(5)가 공존함.
        Unit u1 = new Medic(); 
        Unit u2 = u1; // u1, u2 둘 다 Unit 타입 리모컨으로 같은 Medic 객체를 가리킴

        // u1 리모컨은 Unit 타입이므로, Medic 방이 아닌 Unit 방의 hp를 읽음.
        // 결과: A = 10
        System.out.println("A: " + u1.hp);

이렇게 코드뜯으면서 발견한 내용 


메모리 이중구조 

힙 영역 내부의 

인스턴스가 자녀 규격을 따르고 그 자녀 클래스가 부모 클래스를 상속받는다면

인스턴스 내부의 필드값은 

부모의 인스턴스 필드값 + 자녀의 인스턴스 필드값으로 이중으로 존재한다 



Variable Shadowing 

변수는 숨겨진다


위 처럼 존재하는 경우

부모의 인스턴스 필드값을 자녀의 인스턴스 필드값으로 
가린다

고로 메소드로 해당 인스턴스 값을 변동시키면
자녀 인스턴스 필드값이 변경됨

하지만 부모의 규격을 따르는 리모컨으로 해당 변수값 출력시
숨어있던 부모 인스턴스 필드값이 툭 하고 튀어나옴


Dynamic method dispatch

메소드 실행의 순서

부모 - 상속 자녀 - 

메소드    - 오버라이딩 메소드

이경우 

부모의 리모컨이건
자녀의 리모컨이건 
해당 자녀의 규격을 따르는 인스턴스의 해당 오버라이딩 메소드 실행시

무조건 자녀의 오버라이딩 메소드가 실행되고

자녀의 변수값이 바뀌게됨 

변숫값은 정적바인딩
 즉 컴파일 하는 시점에 내 리모컨이 어떤 규격을따르냐에 따라
변수 어떤걸 부를지 정해짐
고로 그래서
부모 규격떠ㅏ르는 리모컨으로 출력시 
숨어있던 부모영역필드값튀어나오는거임

하지만 메소드는 동적바인딩임
걍 실행시점에서 

오케이 move()메소드 ㅇㅋㅇㅋ
어 부모부터 찍고 아 부모에서 시작된거네 애초에 부모 규격
따르는 리모컨ㅌ이니까 !! ㅇㅇ
그러고 어 근데 이거 ? 오버라이딩되어잇는건데?
어 그럼 오버라이딩된 자녀 move() 로쓰자
자녀규격 따르는 자녀 인스턴스이니까 
이런 런타임 도중에 대상이 정해지는 동적 바인딩의 형태임
이 디테일 놓치지말자
