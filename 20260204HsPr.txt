2. 추상 클래스 (Abstract class)

추상클래스는 

부모클래스 내부의 일정 메소드를 추상화시켜 
그 메소드를 자식클래스에서 강제적으로 오버라이딩하게 하는것이다
오버라이딩하지않고 자식클래스를 만들경우 컴파일에러를 유도하기에 
컴파일 에러로 하여금 자식클래스를 만들때 해당 메소드를 오버라이딩하도록 유도 및 기억하게 할수있다.

해당 추상메소드는 {} 내용값을갖지않는다 ( 왜 why ? ,  추후 자식클래스에서 전부 오버라이딩하며 내용 넣어줘야하기떄문에 )

EX)

Abstract class PiltOver {
	
	int age;
	boolean marriage;
	int speed;


	Abstract void move();
}

class Kait extends PiltOver {
	
	@Override		
	
	void move();{	
		System.out.println("투망을사용해 뒤로 이동하며 앞의적을 공격한다 ");

}

애초에 move 메소드값을 Override로 수정하지않고 그냥 상속받아버리면

class Student {
	
	String name;
	int age;

	Student(String name ,int age); {
	
		this.name = name; //인스턴스변수  (this <- student의 이름은 ) 이 메소드사용시 내가 넣은 name을 삽입한다

그럼 여기서 만약 예를들어  student에 다른 인스턴스변수들이 파져있었고

그럼 이 경우에 생성자 오버로딩이 가능한건 알겠어 그럼

3. 스프링이 무엇인지


우리가 웹사이트를 자바라는 언어로 제작하려고하면

지금 우리가 그냥 자바만 사용해서 제작하는 순수 자바의 형식으로는

정말 1000이라는 노력이 필요하고 

심지어 그 웹사이트가 다수의 사람들이 들락날락거리는 곳이라면 과로로 내가 먼저 죽는다 유지하기전에

그렇기에 

그 웹사이트라는 성의 성벽규격을 제공하는 도구가 스프링이다

고로 자바는 ( 각 벽돌을 어떻게 쌓아야하는지 어떻게 유지해야하는지 배우는거라면 ) 
스프링은 그 벽돌에 대한 이해를 기반으로 이미 준비된 벽돌뭉치성벽규격이다.

4. AWS ( Amazon Web Service)

아마존 웹서비스 에이더블유에스는 
서버를 유지해주는곳이다

예를들어 내가 한 웹사이트를 자바로 만들었다고 가정해보자
그 만든 웹사이트는 그 웹사이트를 유지할 서버가 필요할것이다.
그 서버를 유지하게해주는 컴퓨터를 빌려주는게 아마존 웹서비스이다.
각 나라에 존재하는 수만대의 컴퓨터를 내가 이용한 시간만큼의 비용을 지불하고 1분만에 가입해 
서버( 클라우드)를 제공/유지 받을수있는것이다.
