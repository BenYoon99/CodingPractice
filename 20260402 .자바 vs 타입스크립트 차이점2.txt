📂 [발표 자료] Java vs TypeScript: 결정적 차이점 분석
01. 실행 환경 (Runtime)
"독립적인 중량급 엔진 vs 웹에 최적화된 경량급 엔진"

Java (JVM 기반): JVM(Java Virtual Machine) 위에서 실행됩니다. 운영체제(OS)의 제약 없이 어디서든 동일하게 작동하는 **'독립적 실행 환경'**을 가집니다.

TypeScript (JS 기반): 결국 JavaScript로 변환되어 실행됩니다. 웹 브라우저나 Node.js 환경에서 작동하며, 태생적으로 웹 생태계에 최적화되어 있습니다.

02. 타입 체크의 엄격함 (Type Checking)
"철벽 보안의 정적 타입 vs 유연한 가이드의 점진적 타입"

Java (강력한 구속): 엄격한 정적 타입 언어입니다. 한 번 int로 선언하면 데이터 타입 변경이 절대 불가능하며, 규칙 위반 시 컴파일 자체가 차단되는 강력한 보안성을 자랑합니다.

TypeScript (점진적 타입): 자바스크립트와의 호환성을 중시하는 점진적 타입 시스템입니다. 필요에 따라 타입을 느슨하게 설정(any)할 수 있으며, 실행 시점에는 타입 정보가 사라지는 유연함을 가집니다.

03. 동시성 처리 방식 (Concurrency)
"멀티 스레드의 병렬 처리 vs 싱글 스레드의 비동기 처리"

Java (멀티 스레드): 다수의 CPU 코어를 동시에 활용하는 병렬 처리에 특화되어 있습니다.

원리: CPU가 'Queue(줄 세우기)' 구조로 일을 처리할 때, 여러 개의 줄(스레드)을 만들어 동시에 작업을 뺍니다. 복잡하고 무거운 대규모 연산에 압도적인 속도를 보여줍니다.

TypeScript (싱글 스레드/이벤트 루프): 한 번에 하나의 작업만 수행하는 구조입니다.

특징: 대신 비동기 I/O(Non-blocking) 처리에 최적화되어 있어, 수많은 가벼운 요청(채팅, 알림 등)을 효율적으로 관리하는 데 유리합니다.

04. 변환 방식 (Compile vs Transpile)
"언어의 변신: 바이트코드 vs 자바스크립트"

Java (Compile): 소스 코드(.java)를 컴퓨터(JVM)가 해석하기 최적화된 **'바이트코드(.class)'**로 완전히 변환합니다.

TypeScript (Transpile): 소스 코드(.ts)를 추상화 수준이 비슷한 다른 고수준 언어인 **'JavaScript(.js)'**로 번역합니다. 즉, TS는 JS라는 강력한 엔진을 활용하기 위한 '설계도' 역할을 합니다.

💡 [발표 팁: 마무리 멘트]
"자바는 대규모 금융 시스템이나 기업용 서버처럼 단단한 구조가 필요할 때, 타입스크립트는 빠른 변화가 필요한 웹 서비스나 프론트엔드 개발에 최적화되어 있습니다. 이 두 도구를 적재적소에 사용하는 것이 진정한 엔지니어의 역량입니다."
