1. 다음 용어를 설명하시오.
 
1.1 Network (네트워크)
전송 매체(케이블, 무선 등)를 매개로 연결된 장치(노드)들의 집합체입니다. 
단순히 연결된 상태뿐만 아니라 데이터를 주고받을 수 있는 물리적/논리적 인프라 전체를 의미합니다.

1.2 Networking (네트워킹)
네트워크 시스템을 구축하고 서로 다른 장치 간에 데이터를 효율적으로 교환하기 위해 수행하는 모든 기술적 행위와 통신 과정을 뜻합니다.

1.3 Internetworking (인터네트워킹)
서로 다른 독립적인 네트워크들을 라우터나 게이트웨이 같은 중계 장치를 통해 하나로 연결하여,
 거대한 하나의 네트워크처럼 동작하게 만드는 기술입니다.

1.4 Internet (인터넷)
전 세계에 퍼져 있는 수많은 네트워크가 TCP/IP 프로토콜을 기반으로 상호 연결된 ‘네트워크의 네트워크’입니다. 
인류 최대의 인터네트워킹 결과물이라 할 수 있습니다.

1.5 LAN (Local Area Network)
사무실, 학교, 집 등 비교적 좁은 지역 내의 장치들을 연결한 근거리 통신망입니다. 
전송 속도가 빠르고 에러 발생률이 낮다는 특징이 있습니다.

1.6 MAN (Metropolitan Area Network)
한 도시나 대도시권 정도의 지역을 커버하는 도시권 통신망입니다. 
여러 개의 LAN을 연결한 형태이며, 보통 WAN보다는 좁고 LAN보다는 넓은 범위를 가집니다.

1.7 WAN (Wide Area Network)
국가, 대륙 등 광범위한 지역을 연결하는 광역 통신망입니다. 
주로 전용 회선이나 위성 등을 사용하며, 전송 속도는 LAN에 비해 느리고 복잡한 라우팅이 필요합니다.

1.8 IEEE (Institute of Electrical and Electronics Engineers)
전기·전자·컴퓨터 공학 분야의 세계 최대 기술 전문가 단체입니다.
LAN/MAN 기술의 표준을 정의하는 핵심 기구입니다.
 특히 이더넷과 와이파이 등 네트워크 표준 규격을 제정하는 핵심 기관입니다.




2. OSI 참조 모델이 필요한 이유를 설명하시오 

OSI 참조 모델이 필요한 이유를 아래 기술하겠습니다 교수님.

OSI 7계층 모델은 복잡한 네트워크 통신 과정을 7개로 표준화하여 나눈 것입니다. 이 모델이 필요한 결정적 이유는 다음과 같습니다.

표준화(Standardization): 서로 다른 제조사의 장비 간에도 호환성을 보장하여 통신이 가능하게 합니다.

복잡성 감소: 통신 과정을 단계별로 분리함으로써 설계와 관리를 단순화합니다.

문제 해결(Troubleshooting/트러블슈팅) 용이성: 장애 발생 시 특정 계층의 문제인지
 파악하기 쉬워 유지보수가 효율적입니다. (예: 케이블 문제면 1계층, IP 설정 문제면 3계층)
<-- 왜냐하면 반복문이나 다른 코드를 건들일 필요없이 해당 코드만 고치면 되기에 유지보수가 상당히 용이해지기때문입니다 교수님.

교육 및 학습 가이드: 네트워크의 동작 원리를 체계적으로 이해하는 공통의 언어 역할을 합니다.



3.데이터 패킷의 전달 과정

Client -------- Server 데이터 전달 과정을 
캡슐화와 역캡슐화로  설명하겠습니다.

1. 발신지 (캡슐화) 

사용자가 보낸 편지(데이터)는 상위계층을 지나며 가공됩니다.
그뒤 전송계층에서 포트 번호를 포함한 헤더가 붙어 세그먼트가 되고
, 네트워크 계층에서 IP 주소가 붙어 패킷이 됩니다.
그 이후에 데이터링크/2계층 에서 MAC주소와 에러 체크용 트레일러가 붙어서 
프레임이 된 후 물리계층/1계층을 통해 비트신호로 전송됩니다.

2. 전달 과정
라우터와 스위치등 중간 장비는 헤더 정보를 읽어 최적의 경로로 데이터를 전달합니다.

3. 목적지 ( 역캡슐화)

서버는 비트 신호를 받아 역순으로 헤더를 하나씩 제거/벗겨내기를 하며 데이터를
상위 계층으로 올립니다 , 최종적으로는 서버의 응용 프로그램은 클라이언트가 
보낸 순수한 '편지'의 내용만을 수신하게 됩니다.


4. 대역폭(Bandwidth)과 데이터 수율(Throughput)의 관계

이 두 개념을 지나가는 차의 대수로 비유하여 설명해보겠습니다.

4.1 대역폭

대역폭은 특정 시간 동안 네트워크 회선이 전송할 수 있는 이론적인 최대 데이터 전송량
입니다. 
<-- "도로의 총 차선의 수"

4-2 데이터 수율

특정 시점에 실제로 전송된 유효한 데이터의 양입니다.
<--"실제로 도로를 통과하고 있는 차량 수"


4-3 연관성

데이터 수율은 항상 대역폭보다 작거나 같습니다, 외부요인들( 네트워크 지연, 트래픽 혼잡 
하드웨어 성능저하) 등 다양한 요인들로 인해 실제 수율은 이론상 대역폭만큼
안나오기 때문입니다.
고로 네트워크 실제 성능 파악에는 대역폭보다는 실제 수율에게 가중치가 
더 큰 편입니다..
