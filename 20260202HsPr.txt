1.상속


상속은 클래스 1과 클래스 2가 있다고하면

클래스 2가 클래스 1의 필드와 메소드들을 공통적으로 갖고 +@로 다른내용들을 갖는다면 		
	이 경우에 클래스2 extends 클래스1을 사용해서 클래스1이 갖는 필드와 메소드들을 
		말그대로 클래스 2에 상속해주는것이다.

2. 오버로딩(과적 / Overloading)

오버로딩은 과적이다

			다른 행동이 되기에 그 같은 메소드 ( 같은 자료형 같은 메소드명)이지만 다른 파라미터의 이름 갯수로
				다른 메소드를 만들어주는것이다.
			EX) void 달리기(int run){
					system.out.println("dfsfdsfs")
							}
					void 달리기 (int running){		
					system.out.println("달리기2임당")}

3.오버라이딩(Overriding)

클래스 2가 클래스 1로부터 어떠한 내용을 상속받았다고 가정해보자 
상속받은 내용은 우리가 큰 설계를 하기위해 필수적인 존재라고 가정했을때

 EX) 리그오브레전드 챔피언의 설계도 ( parents )
	야스오 ( child) 아리 (child ) 가렌 (child)

이경우에 hp ad ap moveSpeed , void move ();의 경우 모든 챔피언들이 가져야할 필수적 존재들이다
하지만 이 경우에 아리와 가렌은 뚜벅 뚜벅 걸어감과 다르게 야스오는 E를 타고 이동한다
고로 이동을 그냥 간단히 표현하자면 그건 다른 이동이 되는것이다
고로 이경우 
@Override 
써주고 아래의 상속받은내용인
 void move (){
	system.out.println("E를타고 쓱쓰으윽쓰윽");
};
으로 바꾸어 주어야 하는것이다 .

 5-1 업캐스팅

업캐스팅이란

부모님의 규격을 따르는 리모컨으로   자녀클래스의 규격을 따르는 인스턴스를 조종하는거야

 구성을 보면
	Noxus a = new Darius();

	a라는 녹서스의 규격을따르는 참조변수로  다리우스의 규격을따르는 새로운 인스턴스를 조종하는거야

	 왜 이걸 쓰냐 할수있는데

	예를 들면 우리가 롤을 만드는데 
		녹서스 챔피언들은 20개정도 되잖아
		그럼 그 챔피언들을 모두 같은 움직임을 지시한다고하면 
		그 녹서스 챔피언들을 전부 한번에 조종할수있는 리모컨이 있으면 매우 편하겠지 	
		그게 바로 이 업캐스팅의 사용 의의야
		저렇게 되면 
		메인 메소드에서 a.move();
		박아주면 녹서스 챔피언들 전부 이동시킬수있는거지

6. 동적바인딩 

위 설명과 연결된다

코드하나를 직접짜보자 


class Noxus {

int ad;
int ap;
int moveSpeed;

void ultUse(){
	system.out.println("공격중");
}

class Darius extends Noxus {
	
	
@Override	
	void ultUse(){
		system.out.println("다리우스가 도끼를들어 머리를찍는다");
}

class Katarina extends Noxus {
	

@Override 
	void ultUse(){
		system.out.println("카타리나가 쌍검을들고 회전하며 주위의 적을 공격합니다 " );
}

public Main{

	public static void main(String [] args){
		Noxus a = new Darius();
		Noxus b = new Katarina();
		a.ad = 150;
		a.ap = 0;
		a.moveSpeed = 345;

		b.ad =100;
		b.ap = 150;
		b.moveSpeed =330;
		Noxus c = new Darius();
		
		
		a.ultUse();

	}
	
}

여기서 a.ultUse는 
동적바인딩의 예이다 

왜냐하면

a는 부모의 규격을따르지만

ultUse의 메소드들은 전부 자식들이 오버라이딩한 자기 자신들의 것들이기에 

실행중에  자바가 "부모규격의 리모컨이구나" 라고 자바가 인식하다 어? 각 내용이 다다르네
그러며 자식 클래스에 가서 그 행동을 가져온다 그걸 
동적 바인딩이라고 한다  


부모의 껍데기 메소드인 ultUse가 아닌

실제 객체/인스턴스가 사용하는 오버라이딩한 메소드인 ultUse를 실행시간에 연결(Bind)한다 
이게 동적바인딩임. 


위 경우 모든 챔피언들이 스킬을 사용하게 만들어주고싶다면 메인 메소드에서 한 참조변수를 사용하자 이런 방식으로 접근할게아니라

배열을 이용하고 반복문으로 행동을 반복시켜서 각 챔피언들 궁쓰게해야함

녹서스 배열 제작 <- 각 방에 녹서스 규격따르는 카타 다리 드레이븐 넣어주고
