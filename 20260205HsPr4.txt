인터페이스

인터페이스는 객체를 직접 생성할수가없다 ( 인스턴스생성불가)
생성자를 가질 수 없다
메서드 규약만을 정의하는 타입이다.
(원칙적을로) 추상 메서드만 가진다.
	Java 8+에서는 default, static 메서드를 가질 수 있다.
필드는 public static final 상수만 가질 수 있다.
다중 구현(다중 상속)이 가능하다
구현 클래스는 모든 메서드를 반드시 구현해야 한다.

Static 공용변수

static은 개인이 아니라 공용 이라는 뜻 -> 게시판생각하기

static이 붙은 변수 메서드는 객체마다 따로 생기지 않고 클래스 전체에서 딱 하나만 만들어져서 게시판처럼 함께사용


기본 개념

모든 변수는 메모리 저장된다
int 변수는 4바이트이다.
변수에는 오직 8바이트이하의 값만 넣을수있다.
객체가 필요한 이유
	변수에는 오직 값 하나만 넣을수있기에
	프로그래밍 하다보면 변수에 값을 여러개 넣을 필요가 있을때 가 있기에 
	그래서 고안된게 객체임 
	객체는 커피 캐리어에 비유가능
	커피 캐리어에는 커피 여러잔 담을수있음
	커피 캐리어는 용도에 따라 종류가 다름
	프로그래밍 할때도 상황에 따라 서로다른 객체 필요함
	객체를 일종의 제품으로 보면 객체를 만들기 위해 설계도인 클래스가 필요함
	객체는 너무 커서 변수에 담기 불가능
	그래서 고안된게 리모콘시스템( 참조변수)임
	클래스로는 총 3가지를 normally 가능함
		- 객체 만들수있음(인스턴스)	
		- 그 객체를 조종하는 리모콘 ( 참조변수) 제작가능
		- 그리고 그 객체 리모콘을 담을 변수 제작가능


변수에는 객체 저장 불가
	객체는 너무 크고 변수가 작기때문
'	객체는 여러가지 값(데이터)의 조합이다. 그게 변수에 들어가면 한 덩어리로 해석됨
		즉 변수에 1과 2를 넣으면 다른사람들은 그걸 1과 2의 조합이 아닌 12로 본다
