익명 내부 클래스 

어나니머스 이너 클래스
anonymous inner class

코드예시

Record r = new Record(){
	@Override
	
	public void save(int amount){
		System.out.println(amount ="원 저장중 ... ");
}
}

위 경우를 보게되면

추상메소드만을 보유하는 인터페이스 타입의 참조변수 r을 
생성 후 인터페이스 타입의 인스턴스를 생성하고 그 자리에서 
메소드를 선언해준다 왜 why?
애초에 인터페이스는 추상메소드만을 갖고 있기에
그 규격을 따른다는건 
그냥 말이 안된다 , 인터페이스는 추상메[소드만 갖고있는
껍데기이기에 
new로 땅파고 그 땅판곳에 Record 인터페이스 타입의 객체 만들어도
그건 말이안됨 왜와이
인터페이스 타입의 인스턴스는 추상메소드를 당연히도 갖고 태어나는데
추상메소드는 말그대로 알맹이가없거든
추상메소드니까
그렇기에 객체생성이 불가능한데
그렇기에 그 알맹이를 임시로 그 해당 인스턴스 생성 상황에서 
{}붙여서 오버라이딩쳐주고 임시로 사용하는거임 

이렇게 한번 쓰고 버릴 인스턴스들에 보통 사용함



람다 Lambda

위 코드보면

Record r = new Record (){
	@Override
	public void save (int amount){
		System.out.println(amount + "원 저장!");}
};

인건데 

개발자들은 이렇게 매번 쓰는것에 귀찮음을 느껴서

결국 amount 라는 재료 받아서 원 저장이라고 출력 !이렇게 줄여서 
사용하기로 함

어떻게 

new Record() 이거 어차피 Record 타입 r인걸 아니까
생략쳐주고 

받을 인자타입 파라미터 적어주고 amount


Record r = (x) -> System.out.println(x + " 원 저장 ");

인터페이스 리코드 타입의 참조변수 r에 x라는 int amount의 인자를 넣어주고
그 받은 인자값을 x라는 이름으로 우린 부를꺼고 그 부른x값을
r에 넣어주고 우린 그 뒤 저 행위를 할거야 System ~~~~
ㅇㅇ 


그니까 인터페이스 내부에 추상메소드하나만 존재하고
해당 파라미터가 명확히 존재한다면
그럼 
내가 무슨 매개변수명으로 람다식에서 선언을해주던

어차피 아 int amount의 int 형의 amount 를 그냥 x로 부르는구나하고
알잘딱 자바가 일처리해서 받아와서 그거 r에넣고 
아래 행동 작동시킴
고로 우리는 Record의 save를 그냥 한줄만에 작동시킬수
있는거임
